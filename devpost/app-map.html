Linux Health Copilot

A local Python CLI that explains memory diagnostics, runs only fixed read-only checks after confirmation, and keeps state-changing advice manual.

One request, end to end

Example: ask for available memory and the top three RAM-consuming processes. Gemini classifies and explains; local Python owns the only path to execution.

Three stops in the code

1. Receive the request

main.py → build_parser() → main() defines ask and passes the user's text into the app.

2. Choose a safe route

ask() reads the Gemini action ID. Only memory_process_check reaches the local diagnostic path; stop-process requests use requested_pid() or a confirmed ps refresh.

3. Gate and show results

confirm_read_only() gates run_diagnostic(). interpret_diagnostics() summarizes captured output; show_state_change_suggestion() displays remediation without running it.

To change this, start here

  • Allowed diagnostic commands: MEMORY_DIAGNOSTICS and run_diagnostic().
  • Confirmation text and accepted answers: confirm_read_only().
  • Process ID handling and manual advice: requested_pid(), top_process_pid(), and show_state_change_suggestion().
  • Gemini model and response wording: DEFAULT_MODEL, classify_request(), and interpret_diagnostics().

A practice to reuse

Keep the permission boundary in local code, not in a model's generated text. Here, ask() accepts only a known action ID, confirm_read_only() requires y or yes, and run_diagnostic() receives fixed argument lists with shell=False. The WSL checks showed n cancels, y runs free/ps, and a stop request only displays kill <PID>. For another agent-built tool, define the allowed actions and observable checks before connecting AI output to an operation.
